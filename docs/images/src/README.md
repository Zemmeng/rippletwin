# Diagram sources

The two diagrams in `docs/images/` are generated by a script, so they can be
regenerated, reviewed as a diff and kept in step with the code. Do not edit the
SVG files by hand.

| Output | What it shows |
|---|---|
| `architecture-light.svg`, `architecture-dark.svg` | Browser modules, the Cloudflare Workers and their state, the retired SUMO service, the external LLM and the offline data build |
| `evaluation-flow-light.svg`, `evaluation-flow-dark.svg` | How one works plan goes through the engine, sign reading, SUMO cross-check and plan comparison to the exported pack |

## Regenerate

```bash
python3 docs/images/src/gen_diagrams.py            # writes the four SVGs to docs/images/
python3 docs/images/src/gen_diagrams.py --out /tmp/diagrams   # or anywhere else
```

The script needs only the Python 3.9+ standard library. All layout is computed
in code: text widths use Helvetica/Arial advance widths with a 10% safety margin
(system UI fonts such as SF Pro and Segoe UI run slightly wider). The script
stops with an error instead of writing a broken diagram when

- a line would come closer than 16 px to the side of its box,
- a label would leave the free space it was given,
- a text colour falls below WCAG AA contrast (4.5:1) on its background.

## Render check

```bash
python3 docs/images/src/check_diagrams.py --png /tmp/diagram-png
```

This needs Google Chrome or Chromium (pass `--chrome PATH` or set `CHROME` if it
is not in a standard place). For each SVG it:

1. checks the file is under 300 KB and self-contained: no scripts, images,
   style sheets or links, and no URL other than the SVG namespace;
2. renders a PNG through an `<img>` tag on GitHub's light (`#ffffff`) or dark
   (`#0d1117`) page colour, which is how GitHub displays an SVG in a README;
3. measures every text element in Chrome, once with the declared font stack and
   once forced to Arial, and fails on text closer than 12 px to the side of its
   box, labels that overlap a box or each other, edges that run through text,
   and anything outside the canvas.

The geometry check cannot judge alignment, balance or colour, so open the PNGs
and look at both variants before committing.

## Style

- Canvas 1600 px wide, transparent background, height as needed.
- Font stack `-apple-system, BlinkMacSystemFont, "Segoe UI", Helvetica, Arial,
  sans-serif` only. GitHub serves SVGs through `<img>`, which blocks web fonts,
  external files and scripts. The web app box writes "EN / 中文"; the Chinese
  characters come from the viewer's system fallback font.
- Colours: brand orange `#F07D1A` (from the logo) for Cloudflare runtime and AI
  steps, teal `#0E8F88` for code that runs in the browser and the deterministic
  engine, slate for data and state, grey for external services, inputs and
  outputs. Fills are 10% (light) or 16% (dark) tints of the stroke colour.
- 1.5 px strokes, 10 px corner radius on boxes and 14 px on groups, one arrowhead
  shape. Dashed lines and outlines mark parts retired after the event.

## Embedding

Use a `<picture>` element so GitHub picks the variant that matches the reader's
theme:

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="docs/images/architecture-dark.svg">
  <img alt="RippleTwin system architecture" src="docs/images/architecture-light.svg">
</picture>
```

## Keeping the diagrams accurate

Every label was checked against the code in October 2026. When the code changes,
update the matching text in `gen_diagrams.py`:

| Diagram text | Source of truth |

| Site Worker routes, static assets | `apps/site/src/worker.js`, `apps/site/build.mjs`, `apps/site/wrangler.jsonc` |
| API endpoints, `READINGS`, `LlmBudget`, `WorksiteRegister` | `apps/api/src/worker.js`, `apps/api/wrangler.jsonc` |
| Sign reader chain, 92 pre-computed readings | `apps/api/public/js/reader.js`, `apps/api/public/answers/demo.json` |
| SUMO Worker limits, container size, SUMO version | `apps/sumo/src/proxy.js`, `apps/sumo/wrangler.jsonc`, `apps/sumo/Dockerfile` |
| Detours, logit, calibration, BPR, D/D/1, MSA | `apps/engine/public/js/routes.js`, `choice.js`, `calibrate.js`, `assign.js`, `net.js` |
| Plans A/B/C, hire cost, advisor | `apps/engine/public/js/options.js`, `advisor.js` |
| Data sources and output files | `apps/roads/tools/`, `apps/roads/public/cbd/` |
