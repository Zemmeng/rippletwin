# Pitfalls

Problems the team hit while building RippleTwin, so that nobody hits them twice. Translated from the original Chinese.

- **Append-only** (`merge=union` in `.gitattributes`; `scripts/check.sh` check [3] rejects deleted lines on module branches). Add new project entries at the end of the first table.
- Anything that took more than 15 minutes to solve must be recorded. Teammates' corrections of the AI also go here (area `AI`).
- One entry per line: `| Area | **One-line symptom** | Root cause → fix | Who · date |`. Areas: env / git / frontend / backend / deploy / AI.

## RippleTwin

| Area | Symptom | Root cause → fix | Who · date |
|---|---|---|---|
| frontend | **In the junction simulation, left-turning cars and straight-through cyclists waited for each other: deadlock** | The leader was found with a "heading ray", so vehicles crossing one's own path were also treated as leaders → find the leader by arc length along the same route, accept vehicles on other routes only when they head almost parallel (dot product ≥ 0.9), and list merges separately. An hour-long test run in Node catches it (arrivals fall far below the data) | @Zemmeng · 2026-09-29 |
| frontend | **With the screen off or Chrome in the background, the canvas animation doesn't move and screenshots show only the first frame or two** | The browser doesn't run requestAnimationFrame for pages that aren't visible → write the simulation logic as pure functions that never touch the DOM and verify hour-long results in Node; watch the animation in the preview pane or in a visible foreground tab | @Zemmeng · 2026-09-29 |
| env | **`bash scripts/check.sh` fails with `mod：: unbound variable` (UTF-8 locale)** | bash parsed the full-width comma (U+FF0C) in `$mod，` as part of the variable name, and `set -u` crashed when it couldn't find it → workaround: `LC_ALL=C bash scripts/check.sh`; real fix: change every `$var` immediately followed by a non-ASCII character to `${var}` (about 22 places in check.sh, which only the lead may edit) | @Unzzip · 2026-09-29 |
| env | **On a Mac, `check.sh` crashes on teammates' branches with `mod: unbound variable`, without even printing the summary line** | In a string like `"… module $mod，…"`, where `$var` is immediately followed by a full-width character, macOS bash in a UTF-8 locale swallows the first byte (0xEF) of that character into the variable name as if it were a letter, and `set -u` exits at once; Linux bash 5.2 doesn't reproduce it, a Latin-1 locale does → always write `${var}`; `check [6]` warns about it. Reported by @Unzzip in #5 | @Zemmeng · 2026-09-29 |
| AI | **The AI estimated times itself in messages and reports, and wrote times that hadn't arrived yet (15:38, 15:35) when it was actually 15:31** | It wrote the time by feel instead of reading the "now …" line injected by the hook → always copy the time from the line the UserPromptSubmit hook provides; never estimate | @Zemmeng · 2026-09-29 |
| AI | **Two lead sessions both assigned the same work to @louisxie316-dotcom (T10 basemap vs T11 buildings), and the PRs collided** | The same instruction was given in two sessions, and each opened a PR → assign tasks from one session only; before assigning, check the open PRs and issues for similar work (the requester's original wording wins) | @Zemmeng · 2026-09-29 |
| git | **The Stop gate reported `.claude/worktrees/wf_*` as out of scope, blocking unrelated sessions on every turn** | Workflow worktree isolation creates temporary worktrees inside the repo at `.claude/worktrees/`, which wasn't gitignored, and `check [3]` uses `git ls-files --others --exclude-standard`, so it counted them as this branch's out-of-scope changes → add `.claude/worktrees/` to `.gitignore` (check.sh already passes `--exclude-standard`, so it needs no change); don't delete these directories, other sessions may still be using them | @Zemmeng · 2026-09-29 |
| AI | **After a Workflow with worktree isolation, `check.sh [3]` reported `.claude/worktrees/…` as out of scope and `deploy.sh` reported a dirty working tree** | The Workflow creates temporary worktrees inside the repo at `.claude/worktrees/`, which wasn't in `.gitignore` (the AI may not edit `.gitignore`) → when the Workflow finishes, check with `git worktree list`, and after merging the branch run `git worktree remove <path>` before deploying; the lead adds `.claude/worktrees/` to `.gitignore` | @Zemmeng · 2026-09-29 |
| git | **Stacked PRs (#54 targeting #53's branch): after `gh pr merge 53 --delete-branch`, #54 was closed outright and the local worktree directory holding that branch was deleted** | Deleting the branch from the command line doesn't trigger GitHub's automatic retargeting, and gh removes the worktree together with the local branch → first `gh pr edit <next> --base main`, then `gh pr merge <n> --squash` (without `--delete-branch`), and finally `gh api -X DELETE repos/<owner>/<repo>/git/refs/heads/<branch>` to delete the remote branch. If the PR is already closed: push the branch back from the local commits (pre-push only allows pushing the current HEAD, so switch to the branch in a worktree to push it) → `gh pr reopen` → retarget | @jinmingq · 2026-09-29 |
| AI | **An architecture diagram meant for the judges had to be redone three times: too much small text, task IDs and owners on it, too much empty space in the boxes** | The AI drew it from the internal architecture diagram and crammed in owners, decision IDs and commit gates → diagrams for judges show only the product: each box keeps a name and at most one line, minimum font size ≥ 1/90 of the canvas width, centred text, boxes tight to their content, and a 16:9 canvas like the slides | @Zemmeng · 2026-09-29 |
| git | **Pitch diagrams were kept in `docs/arch/`, so teammates' edits made `check [3]` report changes out of scope** | Only lead branches may write to `docs/arch/` → diagrams and assets that everyone may edit go in `docs/pitch-assets/` (now `docs/hackathon/pitch/`), which a `<handle>/pitch/T<n>-…` branch may write | @Zemmeng · 2026-09-29 |
| AI | **A decision ID was written with a time that hadn't arrived yet (D-0929-2358 when it was actually 23:54), the second time this happened** | The time in the ID and the "written at" line was estimated forward by feel instead of read from the clock → run `date +%m%d-%H%M` before writing a time or a decision ID; the first line of check.sh's output also shows the time | @Zemmeng · 2026-09-30 |
| frontend | **The map's scale bar was 14% off, and the graticule and probe were 120–229 m off** | `geoToWorld()` draws 1 m as about 0.863 page units (and rotates by −20°), but the scale bar assumed 1 unit = 1 m, and `toLL()` neither rotates nor scales → multiply the scale bar by 0.863 (T27 item 6); either make the graticule use the inverse of `geoToWorld`, or turn it off for the demo | @Zemmeng · 2026-09-30 |
| backend | **"Slowed links" painted the existing queues on Flinders St and King St as works ripple** | The engine's `raw.links[].delay_s` is the delay relative to **free flow**, not relative to the same hour without works → use `extra_min` (T28, #79; the difference against no works) and drop the `queue_m>0` condition (#82). It didn't show while the window was small and only appeared once the view was enlarged | @Zemmeng · 2026-09-30 |
| AI | **The user said "let the engine session do it", but no window by that name was in the local session list** | The name the user gave a session in conversation didn't match any window title, and cloud sessions don't appear in `ListAgents` → don't guess, and don't send to two sessions at once (see the T10 / T11 collision above); write a task brief that can be pasted directly, or ask for the window title | @Zemmeng · 2026-09-30 |
| AI | **The user changed the simulation scope several times in one session** | First a single junction and backend only, then the 2×2 of four junctions restored, then once again an explicit "no frontend changes" → follow the latest explicit instruction, deliver only the backend and the interface, record which decision overrides which in the decision log, and keep abandoned drafts out of the delivery | @jinmingq · 2026-09-30 |
| frontend | **In step 2's 2×2 simulation, cars waiting at a red light stopped on crosswalks and inside junctions, and tram tails got stuck in junctions** | `4b-grid.js` hard-coded the stop line 8 units from the junction centre, while the basemap (`2-basemap.js`) draws crosswalks at the cross street's half-width + 0.4…4.0 and stop lines at + 4.6…5.0 (19.6–20 on the main roads); "keep the junction clear" looked only at the vehicle directly ahead, so when that vehicle turned off inside the junction, the tram behind had already entered → place stop lines from the cross-street width (`GRID_W`, aligned with `1-world.js` and checked by a test); when checking whether a whole vehicle fits past the far crosswalk, skip vehicles that are turning off, and use the stopping point of a leader that is braking; after moving the stop line back, don't let the left-turn arc grow with it (the start of the arc would hit vehicles waiting at red in the exit direction, and only 47% of left turns at Little Lonsdale got through) but go straight first and then turn with a radius ≤ 9 | @jinmingq · 2026-09-30 |
| frontend | **Merging #110 (stop lines) into the 4×4 branch gave no conflict in `4b-grid.js`, but the new 4×4 `gridFeeds()` still used the deleted `GRID_P.stopD`, so the top-up entries became NaN** | A clean text merge isn't necessarily a correct one → after a merge, `grep` for the names of deleted parameters. The 4×4 outer ring also exposed five more ways for cars to stop inside a junction or on a crosswalk: the downstream signal turning red just after letting cars in on green; vehicles in the closed lane before the works merging while still inside the junction; two left-turners both assuming the exit had room; a creeping leader in the zip-merge zone not counted as braking; top-up entries inserting cars in front of a tram crossing the junction → before entering a junction, pack the vehicles ahead (including those merging from the closed lane and those turning in at the same junction) up to the next stop line or works segment and check that the vehicle fits; no merging or cutting in inside junctions. A long-hidden deadlock also surfaced: a yielding car stopped 0.3 behind the tail of a merging car, while the minimum merge gap was exactly 0.3 (off by a floating-point hair), so the two cars waited for each other for 21 minutes; the gap was changed to 0.05 | @jinmingq · 2026-09-30 |

## Inherited from the pre-event template (not specific to RippleTwin)

These entries were carried over from the team's pre-event repository template, which collected lessons from earlier projects. Some of the safeguards they describe exist in this repository (the LF rule in `.gitattributes`, check [5] in `scripts/check.sh`), but the incidents themselves happened on earlier projects, not in RippleTwin. The `app.js` they mention belonged to one of those projects.

| Area | Symptom | Root cause → fix | Who · date |
|---|---|---|---|
| env | **macOS has no built-in `timeout` command** | Scripts that run on Linux fail on a Mac with "command not found" → use "run in the background + poll with `kill -0`"; `scripts/check.sh` has a ready-made version | template |
| env | **bash rejects non-ASCII variable names** | An assignment such as `café=1` fails because bash doesn't treat it as an assignment → keep variable, file and directory names ASCII; non-ASCII only in content | template |
| env | **Windows teammates' hooks fail with `bad interpreter`** | The files were saved with CRLF → `.gitattributes` forces LF for `*.sh`; fix files that are already broken with `git add --renormalize .` | template |
| git | **"Is this a repository?" checks fail inside a worktree** | In a worktree `.git` is a file, not a directory → test with `[ -e .git ]`, not `-d` | template |
| git | **The `.wrangler/` cache was committed to the repo** | `git add .` before it was gitignored → it is gitignored now; remove copies already committed with `git rm -r --cached .wrangler` | template |
| git | **Merge conflicts in decisions.md** | Two people appended at the same time → `merge=union` works only for a local `git merge`, not in GitHub's web conflict editor; merge locally | template |
| frontend | **JS/CSS changes don't show up on the live site** | ES modules are cached by URL → after a change, run `bump.sh` to increment `?v=` | template |
| frontend | **A button the user was about to click got swallowed, and a half-chosen dropdown was reset** | `render()` rebuilt the DOM blindly on every poll or push → add a signature guard so the same signature never triggers a rebuild, as `render()` in `app.js` does | template |
| frontend | **After a transform animation was added, the close button could no longer be clicked** | A transform creates a stacking context that covers absolutely positioned siblings → give the button a higher z-index, or animate a child element instead | template |
| frontend | **Effects driven by parsing log text** (`line.includes("hit")`) | Change the wording and every effect breaks → drive effects from a diff of old and new state | template |
| backend | **A Durable Object broadcast its full state and leaked every other user's hidden cards** | The state wasn't trimmed per user → trim it with `viewFor()` before sending, and add a reverse assertion test that other users' secrets never appear in my view | template |
| backend | **An idle Durable Object burned through the quota** | Bot turns looped forever → cap them with `MAX_ROUNDS` | template |
| backend | **Two interleaved requests wrote the saved state as null** | Durable Objects interleave at await points → serialise `commit()`, and make `save()` reject empty values | template |
| deploy | **`env.XXX` is undefined in `wrangler dev`** | `wrangler dev` reads the **module directory's** `.dev.vars` first and falls back to the module directory's `.env`; the repo-root `.env` never reaches the Worker's env (it does reach the wrangler process environment, so never put `CLOUDFLARE_API_TOKEN` in the root `.env`) → put local variables in the module's `.dev.vars` | template |
| deploy | **Renaming a Durable Object class makes the deploy fail with a migration error** | An old migration was edited → never edit old migrations; add a new tag with `renamed_classes` | template |
| deploy | **A deadline was calculated one hour off** | Melbourne switches to daylight saving at 02:00 on 2026-10-04, so a hard-coded UTC offset goes wrong → the conf stores a time-zone name and scripts compute the offset with zoneinfo | template |
| deploy | **"Reset" invalidated every link that had already been sent out** | The reset regenerated the tokens → split it into two buttons, a destructive reset and "clear data, keep links", and use only the latter before a demo | template |
| AI | **A test crashed before printing its counts, but the summary still showed green** | The summary only grepped for the counts and ignored the exit code → `check.sh [5]` counts both a missing count line and a non-zero exit code as failures | template |
| AI | **A Workflow schema with Chinese key names made every agent fail, and the failures were silently counted as "rejected"** | The keys were not ASCII → use ASCII keys, and count failures separately in the summary | template |
| AI | **A multi-agent run was stopped halfway and all its results were lost** | The results existed only in memory → each agent writes its result to `.claude/agent-out/` before returning | template |
| AI | **Third-party API response paths guessed from the docs returned nothing** | The docs didn't match the real responses → make one minimal real request and record the actual path in the "External APIs" section of the module README | template |
| AI | **The AI said it had no tools for rendering or deploying and handed the work back** | It hadn't checked the machine first → check whether `gh`, `wrangler`, `codex` and `python3` are installed, and run whatever can be run | template |
