# T5 Worksite register (proposal #48 step ⑤, backend only) — handoff

*Archived from the hackathon (29 Sep – 1 Oct 2026). Translated from the original Chinese; superseded details are kept as they were.*

## 1. Facts
- What was done: added a worksite register to `apps/api`; not a single line of the web page was changed
  - Endpoints: `GET /api/worksites?from=&to=&status=`, `POST /api/worksites`, `GET` / `PATCH /api/worksites/<id>`; stored in a new Durable Object `WorksiteRegister` (`wrangler.jsonc` migration `v2`; `v1` untouched)
  - A "worksite" = contract §Works plan as it is + `title / kind / status / decision`; the server adds `id / seed / created / updated`; fields outside the allow-list are dropped; sign text follows the spec in `signs.js`
  - No login: registering returns an `edit_token` once (only its SHA-256 is stored); changes must carry the request header `x-edit-token`; the preset worksites are read-only (403 locked); at most 200 entries (409) and at most 500 writes a day globally (429); there is no delete: to withdraw, set `status: withdrawn`
  - 3 preset demo worksites (`public/js/worksites-seed.js`): `W-LONSDALE` / `W-LATROBE` are the same as the engine's `DEMOS`; `W-LTLBOURKE` is a closure on the Lonsdale detour route (Russell St → Little Bourke St) and overlaps Lonsdale for 3 days
  - Browser side, `public/js/worksites.js`: `listWorksites` (falls back to the presets when the endpoint is unreachable), `createWorksite`, `updateWorksite`, `getWorksite`, `overlapping`, `toEngineWorksite`
  - Along the way: `readLimited / json / fail` moved to `src/http.js` (`worker.js` still exports `readLimited`); `signs.js` exports `normSign`; `/api/health` gains `register: bool`; version 0.3.0
- Where it stopped (09-29 20:30): code and tests done and committed on the branch, **not pushed, no PR yet**
- Branch / PR: `jinmingq/api/T5-worksites` (worktree `../hackathon-T5-worksites`, so the main directory is not tied up)
- Verification: `bash apps/api/test.sh` → all passing, summary line in the commit body; `node tests/workerd.test.mjs` ran register → list → wrong token 403 → right token 200 in real workerd
  - Negative assertions (`register.test.mjs`): the token and its hash never appear in any GET / PATCH response, the raw token is not stored, someone else's token cannot make changes, presets cannot be changed, rejected changes are not stored, internal errors are not passed through. Deliberately leaking the hash into the list, or removing the locked check, turns the tests red (tried, then reverted)
  - Overlapping works: locally, using the engine's `conflict()` on main for Lonsdale + Little Bourke, the two times at 8 am on 10-07 and 10-08 clash, with a clash cost of 7,500–10,012 vehicle-minutes; closing one lane of Russell St itself instead gives 0
- Not yet verified: production deployment (Durable Object migration v2 will be created on Cloudflare for the first time); page integration
- Cost this session: 0 (no paid APIs called)
