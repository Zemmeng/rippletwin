# T5 LLM reads the text on signs — handoff (accepting the requests from the #20 engine)

*Archived from the hackathon (29 Sep – 1 Oct 2026). Translated from the original Chinese; superseded details are kept as they were.*

## 1. Facts
- What was done: checked against `reading.js` / `cards.js` / `calibrate.js` of #20 (the lead's engine) as of 09-29 15:20 and found that the engine sends 3 kinds of request that T5 would reject, and that the engine silently treats an error thrown by `readSigns()` as "nobody was persuaded". Changed: accept `kind: "arrow"` (it may have no text); a `read_s` over 120 seconds is treated as 120 (at 5 km/h the engine computes about 137 seconds) and only negative values are rejected; road-name characters match the engine's `cleanName()` (adds `, / ( )`). `tests/engine.test.mjs` tests with the engine's request shapes: 5 vehicle speeds × 4 personas + calibration anchors + arrow boards
- Where it stopped (09-29 15:23): changes done, tests green, not pushed
- Branch / PR: `jinmingq/api/T5-engine-compat` (branched from main after #26 was merged)
- Verification: `bash apps/api/test.sh` → `255 passed, 0 failed`; running `tests/engine.test.mjs` against the old `signs.js` rejects all 20 requests (`bad_kind`), which shows these tests catch the problem
- Integration (15:40, added after #20 was merged into main): `tests/engine-real.test.mjs` runs `prepare` / `evaluate` with the real engine on main + the real T3 network (Bourke Street eastbound), with a VMS + a static sign + two arrow boards: readSigns throws 0 times, `failed = 0`, and the engine gets `advice`. With the old `signs.js`, all 16 readings are lost
- Not yet verified: no integration test in the web page (T2 has not wired up the engine yet)
- Cost this session: 0
