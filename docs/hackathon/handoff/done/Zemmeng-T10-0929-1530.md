# T10 same-origin site shell apps/site: handoff

*Archived from the hackathon (29 Sep – 1 Oct 2026). Translated from the original Chinese; superseded details are kept as they were.*

## 1. Facts
- What was done: new module `apps/site`, one Cloudflare Worker that serves every module. `build.mjs` copies the **git-tracked files** of every module that has a `public/` into `out/<module>/public/` (except site itself; files starting with a dot and symlinks are not copied), then generates a home page `out/index.html`: it contains `data-smoke`; if `apps/web/public/index.html` exists it redirects to `/web/public/`, and `/?list` shows the module list. Routing in `src/worker.js`: `/api/*` is forwarded unchanged if the service binding `API` exists; without the binding, `/api/health` returns `{"ok":true,"v":"site-0.1","mock":true,"api":false}` and everything else returns 503 `api_not_deployed`; `/api/public/*` and all other paths go to ASSETS; no CORS
- Registered in: `DEPLOY_MODULES=site` in `hackathon.conf`, the `apps/README.md` registry, `.github/CODEOWNERS`, `site` (8790) added to `.claude/launch.json`, the module table in `docs/hackathon/plan.md`, a pointer sentence in §0 of `docs/hackathon/deploy-cloudflare-notes.md`; for T10 on the task board, the lead's entry on main (🔨) is authoritative, and this branch adds no row
- Fixed the high-severity findings of the adversarial review (09-29 16:00, `.claude/agent-out/review-site-security.md` R1, R2): the build used to skip only dotfiles, so **gitignored** keys.json, *.pem, raw/ and node_modules/ under `apps/<module>/public/` would go straight from the deployer's computer to the public internet (deploy.sh's `git status --porcelain` cannot see ignored files, so it could not stop this). Now only the files listed by `git ls-files` are copied; if git is unavailable or this is not a repository, it errors out and does not build; a module directory that is a symlink, or a `public/` whose real path escapes `apps/`, is skipped with one printed line. Side effect: during local dev, new files must be `git add`ed before they appear (the build prints "N files not git-added were not copied")
- Where it stopped (09-29 16:00): code and tests done, merged with origin/main (4ed4899); **not deployed yet** (deployment belongs to @unicornnnnnny, D-0929-1322)
- Branch / PR: `claude/lead/deploy-site` (committed only; not pushed, no PR)
- Verification: `bash apps/site/test.sh` → `55 passed, 0 failed`; `WRANGLER_SEND_METRICS=false npx wrangler deploy --dry-run --outdir <temp dir>` bundles, and with `services` enabled it also recognises `env.API (api) Worker`; in local workerd (`unstable_startWorker` from wrangler 4.143.0, not live) went through each request: `/` 200 with data-smoke, `/sim/public/` 200, `/roads/public/cbd/network.json` 200, `/api/health` 200, `POST /api/read` 503, `/api/public/…` handled by the static assets
- Hit during testing: `src/worker.js` exported an extra string constant, and workerd would not start at all (`Incorrect type for map entry 'VERSION'`). Changed it to export only the default; the first test in `worker.test.mjs` checks this
